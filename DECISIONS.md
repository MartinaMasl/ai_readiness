# Decisions

- 2026-10-15: Hosting on Cloudflare Workers (Python Workers) with FastAPI. Reason: chosen by the author. Minimal example in `worker/`.
- 2026-10-15: `index.html` moved to `worker/public/index.html` and served at `/` as a static asset; the FastAPI app is under `/api`. Reason: author's choice, so the report page is on the main URL with no copy step.
- 2026-10-15: Temporary "API test" button at the bottom of `index.html` that calls `POST /api/echo`. Reason: author wants to check the page can reach the API. Remove before the real report.
- 2026-10-15: LangGraph test on Python Workers (no decision yet). The current LangGraph (1.2.x) cannot be installed: it needs `ormsgpack`, which has no Pyodide build. LangGraph 0.4.3 (2025, with langchain-core 0.3) installs and ran a small ask/check/score graph with a follow-up loop under `pywrangler dev`. The test endpoint was removed afterwards.
- 2026-10-15: The flow is written in plain Python, not LangGraph. Reason: only an outdated LangGraph version runs on Python Workers, and because Workers keep nothing between requests the state must be loaded from and saved to D1 by our own code anyway, so LangGraph would add a dependency without saving work. Plain code is also easier to describe in the thesis. Decided by the author.
- 2026-10-15: A subdimension is scored only on the answers given in its own section, not on anything the respondent said earlier in the conversation. Reason: decided by the author, so each score can be traced to the answers to that subdimension's questions.
- 2026-10-15: The rubric moved from `methodology.json` to `worker/src/rubric.json`, and `wrangler.jsonc` has a rule that bundles `.json` files. Reason: a Python Worker only includes files from `src/`, and by default only `.py` files (tested: a JSON file next to the code was not found without the rule). Decided by the author.
- 2026-10-15: Scores are calculated with Python's `Fraction` (exact arithmetic) and turned into floats only for display. Reason: a float mean can come out as 2.9999999… and be floored to the wrong level; a fraction cannot.
- 2026-10-15: The rubric loader checks that every level table (scale, report_levels, subdimension levels) has exactly the levels 0 to 5. Reason: a mistake in the rubric file fails when the Worker starts, not during a conversation.
- 2026-10-15: The report JSON contains no subdimension scores, only the gap texts. Reason: subdimension scores must not be shown to the respondent, and anything in the JSON could be seen in the browser.
- 2026-10-15: `result.html` is a copy of the design in `index.html` with the example values replaced by empty fields that a short script fills from the report JSON. Dimension cards use one `<template>` copied per dimension, so the number of dimensions comes from the rubric. `index.html` stays unchanged until the chat page replaces it in step 3.
- 2026-10-15: Until D1 exists, the report endpoint only knows two made-up ids: `demo` (real rubric, worked example scores) and `demo-four` (Data texts copied as placeholders for the other three dimensions, so the radar chart has four axes). Both are removed in step 3.
- 2026-10-15: Open question to the author: the main gap is shown as "Now: <current level description> Next level: <next level description>" using the full rubric texts; the design showed one short custom sentence. A dimension or overall score that cannot be calculated is shown as "n/a" / "Not available", which the design does not cover.
- 2026-10-15: No evidence at all now gives a score of 0 (flag `insufficient_evidence`), instead of leaving the subdimension out of the mean. The rule `insufficient_evidence` in the rubric was changed accordingly. Reason: the author wants every dimension and the overall score to always have a value in the report. Consequence: "no evidence" and "evidence of no capability" both give 0; the log shows which one it was (evidence "no evidence" for every criterion). The scoring code no longer handles missing scores; a report with a subdimension not yet scored is an error.
- 2026-10-15: The main gap is shown as one sentence from a new rubric field `gap` (levels 0 to 4 per subdimension), for example "Ownership is informal; the next level requires assigned, documented owners." Reason: the full level descriptions made the cards too long; the author wanted one sentence like in the design. The sentences were drafted by Claude from the level descriptions and must be reviewed by the author, since they are methodology texts. Replaces the open question above.
- 2026-10-15: Step 3, fake chatbot. `flow.py` contains the real flow logic (follow-up loop limited by `max_follow_ups`, next subdimension, finish) with two fake functions, `fake_check` (first answer: nothing covered, one follow-up about the first criterion; second answer: everything covered) and `fake_score` (fixed levels 4, 2, 5 by position). Reason: the whole flow, D1 storage and report can be shown without a model; step 5 replaces only these two functions.
- 2026-10-15: D1 has two tables, `conversations` (state as JSON, loaded and saved on every request) and `logs` (log as JSON, written at the start and after every subdimension). Tables are created by `worker/migrations/0001_create_tables.sql`. Reason: Workers keep nothing in memory between requests; one JSON column per conversation is the simplest structure that holds everything.
- 2026-10-15: Each transcript message in the state carries the name of its subdimension. Reason: the log entry for a subdimension and (later) the scoring prompt use only that subdimension's messages.
- 2026-10-15: `index.html` is now the chat page, in the same style as the report. The original design is kept in `result.html` (and in git history). The temporary "API test" button and `POST /api/echo` were removed.
- 2026-10-15: The `demo` and `demo-four` report ids are kept after step 3 (planned to be removed). Reason: the supervisor can see a four-dimension report while the rubric holds only Data.
- 2026-10-15: The intro and closing messages in `flow.py` are drafts by Claude, to be reviewed by the author.
- 2026-10-15: The chat page uses the author's new design (header, progress sidebar, bubbles, typing indicator, dimension dividers). The sidebar and the "Dimension x of n" counter are built from the rubric: `POST /api/conversations` returns an `outline` (dimension and subdimension names) and every response returns the `position` of the current subdimension. "View report" becomes active when the conversation is finished.
- 2026-10-15: Of the design's interactive extras, only the box shown with a follow-up is used (the design called it "checkpoint"; on the page it is labelled with the methodology terms: "Check", "Criteria covered", "Follow-up criterion"). It shows how many criteria the last check found covered and the criterion the follow-up targets; it is removed once answered. The sidebar counts scored subdimensions ("1 / 3 scored") and marks the current one. Quick-answer chips, "Skip", "I'm not sure" and "Save & exit" were left out. Reason: decided by the author; chips would suggest answers and bias the evidence, skipping and resuming are not part of the flow. Known trade-off: the check box shows respondents what is being assessed, which may steer their answers.
